# Product specification

> Written by the human (alone or with an assistant), before the plan. Keep it about behaviour:
> no stack, no file names.

## 1. Problem and people
Who has which problem today, and what changes for them.

## 2. Rules
The behaviour that must hold, each rule numbered in `../requirements.md`.

## 3. Journeys
Step by step, from the user's side, including errors and empty states.

## 4. Acceptance cases
Concrete examples per journey: given, when, then. These are where test expectations come from.

## 5. Out of scope
What this version deliberately does not do.
